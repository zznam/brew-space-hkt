# FE1 Merchant POS (selling side) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a cashier a working walk-in order flow (menu → cart → pay → ticket board) on top of the existing merchant live-floor screen, without touching BE-owned `src/core/domain.ts`/`billing.ts`. This is Phase 1 (weeks 2–3) of `docs/fe1-pos-plan.md`'s §5 table; `ShiftScreen` and `RefundScreen` (weeks 6–7) are a separate follow-up plan, not covered here.

**Architecture:** A new, isolated `src/features/merchant/pos` module owns its own order/ticket state (a zustand vanilla store, mirroring `src/core/store.ts`'s pattern but not persisted and not touching `src/core`). `PosScreen` composes a menu grid and a cart panel against that store; `TicketBoardScreen` reads the same store to show paid orders moving through fulfilment. Both are new routes under `app/merchant/`. This is "Approach B" from `docs/fe1-pos-plan.md`: a throwaway mock shaped like the PRD's fields, swapped for the real API later.

**Tech Stack:** Expo Router, React Native, TypeScript, zustand/vanilla (already a dependency), vitest for pure logic, Playwright for the UI flow. No new dependencies.

**Spec:** `docs/fe1-pos-plan.md` (design doc, Approach B) and `docs/mvp-features.md` rows F010, F012, F017, F020, F022, F023, F034, F035, F038.

## Global Constraints

- Money is an integer VND; reject non-safe-integers and negatives, same rule `calculateBill` already enforces.
- Reuse `getVenue`, `venues`, `formatMoney` from `@/core`; never reimplement venue/menu lookups or money formatting.
- Do not modify `src/core/domain.ts` or `src/core/billing.ts` — those are BE-owned (`CONTRIBUTING.md`). This module reads core's venue/menu data only.
- Path alias `@/*` → `./src/*` (`tsconfig.json`).
- Routes in `app/` only re-export a feature screen (see `app/merchant/live-floor.tsx`); no business logic in route files.
- Reuse `Button`, `Card`, `Heading`, `styles`, `colors` from `@/components/ui`; no new design system.
- Every interactive element needs `accessibilityRole`/`accessibilityLabel`/`accessibilityState`; status must be readable as text, not color alone (matches `SeatMap.tsx`).
- `npm run check` (typecheck, lint, vitest) and `npm run build:web` must pass before each commit, per `CONTRIBUTING.md`.
- No AsyncStorage/persistence for this module — it's explicitly a throwaway mock (Approach B); state resets on reload. State is a module-level singleton so `PosScreen` and `TicketBoardScreen` see the same orders.

## Review Focus

- **Paying an empty cart.** A reasonable cashier expects the "Pay" action to be disabled or refused when an order has no lines — pin this in Task 1's tests.
- **Negative or zero quantity via the quantity control.** Decrementing past 1 should remove the line, never go negative — pin this in Task 1's tests.
- **Cancelling an order that is already paid.** The PRD only allows cancel before payment (`§4`); pin this in Task 1's tests.
- **Marking an item sold out while it's already in an open cart.** PRD says sold-out hides the item from *new* carts, not existing lines — an existing cart line must survive, but no new quantity can be added once sold out. Pin this in Task 1's tests.
- **Advancing a ticket out of sequence** (e.g. `queued` straight to `served`). F034's queue is `queued → preparing → ready → served`; skipping steps should be refused. Pin this in Task 1's tests.

**Interfaces:**
- Consumes: `ActionResult` type and nothing else from `@/core` (no runtime import of domain/billing).
- Produces (for Tasks 2–4):
  - `type PosOrderStatus = 'draft' | 'awaiting_payment' | 'paid' | 'completed' | 'cancelled'`
  - `type FulfillmentStatus = 'queued' | 'preparing' | 'ready' | 'served'`
  - `type PaymentMethod = 'cash' | 'online'`
  - `interface PosOrderLine { menuItemId: string; name: string; unitPrice: number; quantity: number }`
  - `interface PosOrder { id: string; venueId: string; seatId: string | null; lines: PosOrderLine[]; status: PosOrderStatus; fulfillment: FulfillmentStatus | null; paymentMethod: PaymentMethod | null; createdAt: number }`
  - `function calculateOrderTotal(order: PosOrder): number`
  - `interface PosStore { orders: PosOrder[]; soldOutItemIds: string[]; createOrder(venueId: string, seatId: string | null): string; addLine(orderId: string, menuItemId: string, name: string, unitPrice: number): ActionResult; setLineQuantity(orderId: string, menuItemId: string, quantity: number): ActionResult; toggleSoldOut(menuItemId: string): void; pay(orderId: string, method: PaymentMethod): ActionResult; cancelOrder(orderId: string): ActionResult; advanceTicket(orderId: string, next: FulfillmentStatus): ActionResult; reset(): void }`
  - `addLine` semantics (pin these in tests, not just prose): refuses with `ActionResult { ok: false }` if `menuItemId` is in `soldOutItemIds`, or if the order's `status` is not `'draft'`. Otherwise, if the order already has a line for `menuItemId`, increments that line's `quantity` by 1 (ignoring the passed `name`/`unitPrice`, which only matter for the first insert); otherwise appends a new line with `quantity: 1`. There is deliberately no separate "increment" action — `MenuGrid`'s "add" button always calls `addLine`.
  - `status` note: `'awaiting_payment'` is reserved for the future real-API swap (an async/online-payment pending state). This mock's `pay()` resolves synchronously straight from `'draft'` to `'paid'` for both `'cash'` and `'online'` — it never produces `'awaiting_payment'`. Don't implement a pending delay; that belongs to the real integration.
  - `setLineQuantity` uses the same "only on a `'draft'` order" guard as `addLine` (share a small internal `isEditable(order)` helper rather than duplicating the check).
  - `function createPosStore(): StoreApi<PosStore>` (zustand vanilla `createStore`, same shape as `src/core/store.ts`'s `createAppStore`)
  - `export const posStore = createPosStore()` and `export const usePosStore = <T>(selector: (state: PosStore) => T) => useStore(posStore, selector)` from `usePosStore.ts`

```ts
// tests/posStore.test.ts
import { describe, expect, it } from 'vitest';
import { calculateOrderTotal, createPosStore } from '../src/features/merchant/pos/posStore';

describe('pos order totals', () => {
  it('sums line unit price times quantity', () => {
    const order = { id: 'o1', venueId: 'grind', seatId: null, status: 'draft' as const,
      fulfillment: null, paymentMethod: null, createdAt: 0,
      lines: [{ menuItemId: 'grind-drink', name: 'Cold brew', unitPrice: 45000, quantity: 2 }] };
    expect(calculateOrderTotal(order)).toBe(90000);
  });
});

describe('pos store', () => {
  it('creates a draft order scoped to a venue and optional seat', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', 'grind-seat-1');
    const order = store.getState().orders.find((o) => o.id === id);
    expect(order?.venueId).toBe('grind');
    expect(order?.seatId).toBe('grind-seat-1');
    expect(order?.status).toBe('draft');
  });

  it('adds a line and increases total', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    expect(store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000).ok).toBe(true);
    const order = store.getState().orders.find((o) => o.id === id)!;
    expect(calculateOrderTotal(order)).toBe(45000);
  });

  it('increments the existing line instead of duplicating it', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000);
    store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000);
    const order = store.getState().orders.find((o) => o.id === id)!;
    expect(order.lines).toHaveLength(1);
    expect(order.lines[0].quantity).toBe(2);
  });

  it('refuses adding a line to an order that is already paid', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000);
    store.getState().pay(id, 'cash');
    expect(store.getState().addLine(id, 'grind-snack', 'Croissant', 35000).ok).toBe(false);
  });

  it('refuses paying an order with no lines', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    expect(store.getState().pay(id, 'cash').ok).toBe(false);
  });

  it('setLineQuantity removes the line at zero and rejects negative', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000);
    expect(store.getState().setLineQuantity(id, 'grind-drink', -1).ok).toBe(false);
    expect(store.getState().setLineQuantity(id, 'grind-drink', 0).ok).toBe(true);
    expect(store.getState().orders.find((o) => o.id === id)!.lines).toHaveLength(0);
  });

  it('keeps an existing cart line when the item is marked sold out, but blocks new adds', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000);
    store.getState().toggleSoldOut('grind-drink');
    expect(store.getState().orders.find((o) => o.id === id)!.lines).toHaveLength(1);
    expect(store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000).ok).toBe(false);
  });

  it('pays an order with lines, moving it to paid with a queued ticket', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000);
    expect(store.getState().pay(id, 'cash').ok).toBe(true);
    const order = store.getState().orders.find((o) => o.id === id)!;
    expect(order.status).toBe('paid');
    expect(order.fulfillment).toBe('queued');
  });

  it('refuses cancelling an order that is already paid', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000);
    store.getState().pay(id, 'cash');
    expect(store.getState().cancelOrder(id).ok).toBe(false);
  });

  it('advances tickets one step at a time and refuses skipping', () => {
    const store = createPosStore();
    const id = store.getState().createOrder('grind', null);
    store.getState().addLine(id, 'grind-drink', 'Cold brew', 45000);
    store.getState().pay(id, 'cash');
    expect(store.getState().advanceTicket(id, 'ready').ok).toBe(false);
    expect(store.getState().advanceTicket(id, 'preparing').ok).toBe(true);
    expect(store.getState().advanceTicket(id, 'ready').ok).toBe(true);
    expect(store.getState().advanceTicket(id, 'served').ok).toBe(true);
  });
});
```
